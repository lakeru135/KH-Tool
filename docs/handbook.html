Your first batch run

KH-Tool opens many Revit models for you, one after another, and writes down what it found. You set it up once, press Run and walk away, or give it a time and let it run overnight. Everything below assumes you have never opened it before.

01

Install it

One installer, KhBatchRunner-Setup.exe, covers Revit 2024, 2025, 2026 and 2027. It installs for whichever of those years it finds on the PC.

  1. Close Revit.

    Revit reads its add-in folder only when it starts, and the installer writes into that folder.

  2. Right-click the setup file and choose Run as administrator.

    It installs for every account on the PC, which needs admin rights.

  3. Windows says “Windows protected your PC”.

    Click More info, then Run anyway. The file is not signed with a commercial certificate.

  4. Start Revit.

    If Revit asks about an unsigned add-in, choose Always Load.

Coming from “ACC Batch Script Runner” 1.x

The 2.x installer replaces it in place. On first start your settings and model sets are copied across and the old folder is kept as a backup. Each schedule is registered under its new name the first time Revit starts normally.

02

Find the tab, and sign in

A ribbon tab called KH-Tool appears beside Revit's own tabs. Its panels, left to right: Setting, Batch Run, Schedule, Multi Model Check, Model Batch Action, NWD Helper, Forma Batch Action, Excel Link and Parameter Helper. You will spend your first week in the first four.

On Setting: About, Edit Sets (a dropdown with Edit Model Set and Edit DYN Script Set), Import / Export Settings, and the two AI Bridge / AI Code toggles, which are off at every Revit start.

Sign in first

The tool reads your Forma projects with the Autodesk account Revit itself is signed in to. It never asks for a password. If model lists come up empty, sign in at the top right of Revit and try again.

The separate DRW Helper edition has its own tab with the drawing tools; see section 6.

03

Make a model set

A model set is a saved list of models, the thing you point a run at. Open Setting › Edit Sets › Edit Model Set.

  1. Click New and browse to your project folder in the Forma tree.

  2. Tick the models you want and add them to the set.

    Hold Shift to tick a range. You can also add .rvt files from disk.

  3. Or add a whole folder.

    Usually better: the set stores the folder, not today's file list, and scans it again on every run. Models added next month are picked up without touching the set.

  4. Name the set and click Save set.

    Name it after what it is for, such as Weekly SITE1 ARCH.

Greyed-out models and sets

A model saved in a newer Revit than the one you have open is greyed with its year beside it. Run it from the matching Revit.

A whole set greyed with no access as <you> means the signed-in Autodesk account cannot open that project. You can still pick it: the check can be wrong, so it warns and never blocks. Every dialog that lists model sets shows this the same way.

04

Run something safe

Make your first run a read-only check on a small set. Click Multi Model Check › Get Phase & Workset.

  1. Tick one model set.

    Three or four models is plenty.

  2. Change When finished to Close files.

    The default, Close Revit when complete, is right for real runs but Revit disappears and you never see the summary.

  3. Set a Destination folder and a Project log name.

    The folder starts on the last one you used. The log name is a short project code stamped into every file name.

  4. Click Run, then leave Revit alone.

    A progress window lists each model. Revit is driving itself; do not click around in it.

Even quicker: the model you have open

With a project open, tick Run on active model only. Nothing opens or closes, no log is written and the result appears in a grid on screen. A tool that changes the model leaves the change unsaved so you can look first.

Then try Batch Run

Batch Run › Batch Run has three lists: saved model sets, one-off models, and the actions and Dynamo script sets to perform. Tick several actions and they run top to bottom on each model; Move ▲ / Move ▼ change the order. Leave Model treatment on Don't sync (dry run) until you have read a dry-run log.

Before you ever pick Sync

A batch that syncs is the one thing here that cannot be undone, and it does it to every model in the set before you can look at the first one. Run it dry first, on copies.

05

What every tool shares

Learn one dialog and you know the rest. Every tool that runs over models follows the same five habits.

HabitHow it works everywhere
Pick a model setThe same list of saved sets, with the same greying for sets your account cannot open. Where the list has tick boxes (the check and action buttons, Batch Run, Export NWC, Export IFC + Data) tick as many sets as you like: they run as one list, and a model that is in two sets runs once. The other tools take one set.
Save your inputsType a name in the set box and click Save set. Saving over an existing name asks first. Saving a loaded set under a new name renames it; use Duplicate to make a copy. Delete asks first. The dialog reopens with what you last ran.
Run on the open modelRun on active model only: no log, nothing saved or synced, result on screen. The checkbox sits under the model-set list and only appears when a project model is open before you click the button.

Run in parallelA big set is split into groups, each in its own Revit, as many at once as the PC's memory allows. A supervisor reruns any model a crashed Revit took with it. Revit is never force-closed.

07

Run it overnight

Open Schedule › Schedule Run. The bottom half is the Batch Run form. The top half adds a name, a recurrence (once, daily, weekly), a date and a time. Click Save schedule and Windows Task Scheduler starts Revit at that time. Press Run now first to try the exact selection.

  • Leave When finished on Close Revit when complete. A scheduled run has to end by itself.
  • Stay logged on. Locking the screen is fine. Signing out or shutting down means nothing runs.
  • Space schedules apart. Each run works out how many Revits the PC can carry for itself alone, so two that overlap overload it.
  • Untick On to pause one. The Windows task is kept and Run now still works.
You get a notification

A Windows notification shows the succeeded and failed counts when a run ends.

08

Where results land

The run log: did it work?

…\Log\20261113_2100_SITE1_Get Phase & Workset.csv

One file per run in a Log sub-folder, one row per model per task with a status and a message. Open this first. Parallel Revits all write to this one file.

The detail files: what it found

Each task has its own sub-folder and one file per day; a second run the same day appends to it. Exports write their files to the output folder named in their options set.

Reading a failure

A failed model carries the reason in its Message column. Fix the cause and re-run just those models as one-off models in Batch Run.

09

Move it to a new PC

Setting › Import / Export Settings writes one .zip with your model sets, script sets, folder sets and every tool's saved inputs. Import it on the new PC; if something already exists you choose once to skip, overwrite or keep both.

Schedules do not travel

Half of a schedule lives in Windows Task Scheduler. Re-create schedules on the new PC.

10

When it goes wrong

Half my sets are greyed out

Revit is signed in as an account that cannot open those projects. Check the account at the top right of Revit.

A Revit window closed on its own

Expected. Each group closes its own Revit when it finishes. If a model crashes Revit while opening, the run restarts that group with the models it had not finished.

A run says a group needs attention

That Revit was left open for you to look at. The tool never force-closes Revit. Look at the window before you close it.

Nothing happened at the scheduled time

  • Were you still logged on?
  • Is the schedule's On box ticked?
  • Was a Revit already open with a dialog waiting, such as the unsigned add-in prompt?

An export of the open model looks incomplete

It exports what is open. Open the missing worksets and run it again, or run it over a model set, where the tool opens the worksets the export view needs.

Reporting a problem

Use the Start menu shortcut Collect diagnostics report after the run that went wrong. It gathers the run logs and Revit journals into one ZIP on your Desktop, changes nothing and needs no admin rights. Attach it to an issue at github.com/lakeru135/KH-Tool/issues, after checking it holds nothing confidential.
